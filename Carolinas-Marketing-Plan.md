## Flyer QR Code — Mobile UX Flow Assessment

**Flow:** QR scan → myaiworker.online → hero + Max teaser → tap "Ask Max" → voice/chat call

**What's working well:**
- Full-screen intro overlay fires on mobile tap — good for first-time QR visitors
- Max teaser bubble appears after 2 seconds — keeps bounce rate low
- Mic permission notice handles iOS/Android differences
- Pricing is above the fold on mobile

**Friction points to address (ranked by impact):**
1. **Mic permission is jarring on first visit** — iOS users hit a browser permission prompt immediately when they start a voice call. Consider adding one sentence of warning before the call starts: "You'll be asked for mic access — that's just so Max can hear you." (Currently the mic notice exists but only shows after permission is denied.)
2. **Stripe checkout after Max closes** — when Max injects the Stripe payment buttons, they open in a new tab. On older iOS Safari, popups can get blocked. Test with `target="_blank"` on the Stripe links and ensure Max's injected buttons use `window.open` with user gesture.
3. **No confirmation after Stripe payment** — verify the Stripe success URL redirects to `onboard.html`. If Stripe success URL isn't configured, buyers land on a Stripe confirmation page with no path back to onboarding. **Flag:** Check your Stripe payment link settings for the "After payment" redirect URL — it should be `https://myaiworker.online/onboard.html?plan=receptionist` (or `?plan=busybiz`).
